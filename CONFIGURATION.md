# CONFIGURATION.md

## Files

| File | Purpose | Sensitivity |
|---|---|---|
| `config/settings.json` | public/non-secret deployment settings | low |
| `config/secrets.env` | admin API token | **secret**, chmod 600, gitignored |
| `config/sing-box.json` | generated server config with user UUIDs | sensitive, chmod 600, gitignored |
| `database/tiktunnel.db` | accounts, subscription tokens, audit events | sensitive, gitignored |
| `subscriptions/*.txt` | base64 VLESS URIs, filename is SHA-256 prefix of token | sensitive, chmod 600 |

## `config/settings.json`

```json
{
  "listen_host": "0.0.0.0",
  "listen_port": 8443,
  "api_host": "127.0.0.1",
  "api_port": 3000,
  "max_users": 3,
  "public_host": "127.0.0.1",
  "security": "none",
  "sni": "",
  "transport": "tcp",
  "flow": "",
  "mode": "lab-local-only"
}
```

- `listen_port`: VLESS port. Must be free and reachable from clients.
- `api_host`: keep `127.0.0.1` — the admin API must never be exposed publicly.
- `max_users`: hard cap on simultaneously active accounts (revoked/expired ones do not count).
- `public_host` / `security` / `sni` / `flow`: used only when building VLESS URIs for subscriptions. They do **not** enable TLS by themselves.

After editing settings, run:

```bash
./scripts/apply-config.sh
node subscriptions/render.js
```

## Upgrading to TLS (requires a domain you control)

1. Obtain a valid certificate/key (ACME with a domain pointing to this server, or an existing valid pair). Store them in `config/certs/` with chmod 600. **Never use a self-signed cert or disable verification.**
2. Add to the VLESS inbound in `server/render-config.js`:

   ```json
   "tls": {
     "enabled": true,
     "certificate_path": "config/certs/fullchain.pem",
     "key_path": "config/certs/privkey.pem"
   }
   ```

3. Set in `config/settings.json`:

   ```json
   "public_host": "vpn.example.com",
   "security": "tls",
   "sni": "vpn.example.com",
   "flow": "xtls-rprx-vision",
   "mode": "production-tls"
   ```

4. Validate and apply:

   ```bash
   bin/sing-box check -c config/sing-box.json
   ./scripts/apply-config.sh
   node subscriptions/render.js
   ```

   `flow` must be omitted (empty) on the client side if TLS is used without XTLS Vision in a client that does not support it; Shadowrocket generally supports `xtls-rprx-vision` with TLS, but verify on the actual device.

5. Verify inbound connectivity from an external network before declaring success.

## REALITY (alternative, no certificate)

REALITY still needs a **transparent TCP connection** to the server and a real SNI target. This environment's tunnel terminates TLS and demands browser auth, so REALITY cannot be tested here. If moving to a VPS with a public IP:

- configure `tls.reality` in the inbound with `short_id`, `server_name` and a valid `certificate`/`key` pair generated by sing-box tooling;
- set `security=reality`, `sni=<server_name>`, `flow=xtls-rprx-vision` in settings;
- confirm the installed Shadowrocket version supports REALITY before rollout.

## Account lifecycle

- Create → unique UUID + unique subscription token generated with `crypto.randomUUID()` / 24 random bytes.
- Disable → `PATCH {"enabled":false}` keeps the account but removes it from the server config.
- Expiry → `expires_at` ISO timestamp; expired accounts are filtered out of config and subscriptions.
- Revoke → `DELETE` sets `revoked_at`, removes it from config immediately.

Every change re-renders `config/sing-box.json`, validates it with `sing-box check`, and restarts sing-box only.

## DNS and routing

`dns.servers` uses the `local` resolver (system resolver via systemd-resolved/DBus) — minimal memory, no remote DNS queries from the server. Routing uses `final: "direct"` with no rule sets, geoip or sniffing, which keeps CPU/RAM low. TUN is not used.
